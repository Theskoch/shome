# CLAUDE.md

Контекст проекта для Claude Code и для людей, которые видят репозиторий впервые.

## Что это

Self-hosted дашборд домашних сервисов: страница с карточками-ссылками (vCenter, ESXi и т.п.),
вход через LDAP/Active Directory, редактирование карточек, иконок и фона прямо из UI.

Бэкенд — один файл [app.py](app.py) на Flask. Фронтенд — статические `.htm` с инлайновым JS,
без сборки, без npm, без фреймворков. Базы данных нет: всё состояние в JSON-файлах на диске.

Исторически проект жил на IIS (отсюда имя `iisstart.htm`), сейчас это обычное Flask-приложение.
Контур — только локальная сеть, наружу не публикуется.

## Раскладка

```text
app.py              # весь бэкенд: роуты, LDAP-аутентификация, API, раздача статики
iisstart.htm        # дашборд (главная страница, вся логика UI внутри <script>)
login.htm           # страница входа
css.css             # стили обеих страниц
assets/             # SVG-иконки UI, favicon, шрифты — статика, отдаётся как /assets/*
App_Data/           # состояние при локальном запуске (gitignored)
  services.json     #   карточки сервисов
  settings.json     #   настройки UI (фон)
  ldap_config.json  #   конфиг LDAP + secret_key сессий
uploads/            # загруженные иконки и фоны (gitignored)
_pydeps/            # вендоренные зависимости со времён IIS (gitignored, см. ниже)
docker/             # Docker-деплой; конфиг и данные лежат рядом с compose, не в образе
```

## Запуск

Docker (основной способ) — см. [docker/README.md](docker/README.md):

```bash
cd docker && cp .env.example .env && docker compose up -d
```

Локально:

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r docker/requirements.txt
python3 app.py            # http://localhost:8080
```

## Как устроена конфигурация

Пути читаются из переменных окружения с фолбэком на историческую раскладку рядом с `app.py`.
Благодаря этому Docker держит конфиг и данные вне образа, а локальный `python3 app.py`
продолжает работать без единой переменной:

| Переменная | Дефолт | Что это |
|---|---|---|
| `SHOME_APP_DATA_DIR` | `./App_Data` | Каталог состояния (`services.json`, `settings.json`) |
| `SHOME_UPLOADS_DIR` | `./uploads` | Каталог загруженных картинок |
| `SHOME_LDAP_CONFIG` | `$SHOME_APP_DATA_DIR/ldap_config.json` | Файл конфига LDAP |
| `SHOME_SECRET_KEY` | ключ из `ldap_config.json` | Переопределение ключа подписи сессий |
| `SHOME_PORT` | `8080` | Порт дев-сервера (только при `python3 app.py`) |
| `SHOME_DEBUG` | `0` | Flask debug для дев-сервера |
| `SHOME_LOGIN_MAX_ATTEMPTS` | `10` | Попыток входа с одного IP до паузы |
| `SHOME_LOGIN_BLOCK_MINUTES` | `5` | Длительность паузы |
| `SHOME_TRUST_PROXY` | `0` | Брать IP клиента из `X-Forwarded-For` (только за реальным прокси) |

`secret_key` должен быть стабильным между рестартами, иначе у всех разлогинятся сессии.

## Два режима LDAP

Режим определяется составом ключей в `ldap_config.json` (полная таблица — в [README.md](README.md)):

1. **Поиск через сервисную учётку** (для AD): `bind_dn` + `bind_password` + `search_base` +
   `search_filter`. Опционально `required_group_dn` ограничивает вход по группе.
2. **Шаблон DN**: только `user_dn_template` (например `uid={username},ou=users,dc=home,dc=local`).
   Если он задан, он выигрывает — режим поиска не используется.

## Модель данных и подводные камни

- **Все пути иконок нормализуются** через `normalize_icon_path()` при каждом чтении и записи
  `services.json`. Легаси-префиксы (`/assets/images/...`, голое имя файла) переписываются в
  `/uploads/<file>`. Меняешь формат хранения иконок — правь эту функцию, она единственная точка истины.
- **`cleanup_unused_uploads()` удаляет файлы** из `uploads/`, на которые не ссылается ни одна
  карточка и которые не являются текущим фоном. Вызывается на каждом `POST /api/services`.
  Любой новый способ ссылаться на загруженный файл обязан быть учтён здесь, иначе файл сотрут.
- **`_uploads_name_map_cache`** — регистронезависимая карта имён файлов в `uploads/`, строится
  лениво. После любой записи/удаления в `uploads/` зови `invalidate_uploads_name_map()`.
- Нет `services.json` → `GET /api/services` отдаёт `{"initialized": false}`, и UI показывает
  онбординг. Пустой список `[]` — это уже инициализированное состояние, онбординга не будет.

## Раздача статики (важно)

`static_folder` намеренно указывает на `assets/`, а **не** на корень проекта. Раньше он указывал
на корень с `static_url_path=""`, из-за чего по HTTP без всякой авторизации отдавались `app.py`,
`App_Data/ldap_config.json` (вместе с паролем bind-учётки AD) и `.git/`. Не возвращай static-folder
на корень проекта — добавляй точечные роуты, как сделано для `/css.css`.

Публичные роуты (без сессии): `/login`, `/api/auth/*`, `/assets/*`, `/css.css`.
Всё остальное, включая `/uploads/*`, закрыто через `@require_auth` либо редиректит на `/login`.

`login.htm` не тянет ничего из `/uploads` — фон логина живёт в `css.css`. Поэтому загрузки можно
держать закрытыми; не «открывай» их ради страницы логина, ей это не нужно.

Отдача из `/uploads` идёт с `X-Content-Type-Options: nosniff` и `Content-Security-Policy:
default-src 'none'; sandbox`. Это нужно из-за SVG: внутри `<img>` он безопасен, но при прямом
переходе на `/uploads/x.svg` скрипт внутри него выполнился бы на нашем origin.

## Троттлинг входа

`/api/auth/login` даёт `SHOME_LOGIN_MAX_ATTEMPTS` неудачных попыток с одного IP, затем отвечает
`429` в течение `SHOME_LOGIN_BLOCK_MINUTES`, после чего счётчик обнуляется и выдаётся новая пачка.
Успешный вход сбрасывает счётчик. Смысл — не дать перебору дойти до AD и залочить учётки по
доменной политике блокировок.

Счётчик живёт **в памяти процесса**, поэтому gunicorn запускается с `--workers 1 --threads 4`
(см. [docker/Dockerfile](docker/Dockerfile)). Добавишь воркеров — каждый заведёт свой счётчик, и
реальный лимит вырастет кратно их числу. Понадобится масштабирование — выноси состояние в общее
хранилище, а не увеличивай воркеры.

Ключ троттлинга — `request.remote_addr`. За reverse proxy это адрес прокси, и все клиенты
сливаются в один ключ, блокируя друг друга. Поэтому `SHOME_TRUST_PROXY` = **число хопов прокси**
(за Nginx Proxy Manager — `1`), и при значении > 0 приложение оборачивается в `ProxyFix`.

`ProxyFix` берёт из `X-Forwarded-For` запись, добавленную нашим прокси (N-я справа), а не первую.
Это принципиально: левые записи приходят от клиента. Не заменяй его ручным
`request.headers["X-Forwarded-For"].split(",")[0]` — так лимит обходится подстановкой заголовка.
И не завышай число хопов: каждый лишний хоп сдвигает выбор влево, в зону, подконтрольную клиенту.

## Зависимости

- Рантайм: `flask`, `werkzeug`, `ldap3`; в Docker дополнительно `gunicorn`. Пины — в
  [docker/requirements.txt](docker/requirements.txt).
- `_pydeps/` — вендоренные пакеты со времён IIS, добавляется в `sys.path` в начале `app.py`.
  **`ldap3` там нет**, поэтому запуск с опорой только на `_pydeps` падает на импорте. Docker-образ
  ставит зависимости через pip и `_pydeps/` игнорирует. Каталог держим только ради старого IIS-хоста.

## Конвенции

- Комментарии в коде и docstring-и — на английском; README и пользовательская документация — на русском.
- API отвечает `{"success": bool, "message": str}` и осмысленным HTTP-кодом; фронт смотрит на `success`.
- Ошибки LDAP возвращаются пользователю as-is (`str(exc)`) — удобно для дебага, но текст сервера
  утекает на страницу логина. Учитывай при изменениях.
- Никаких новых зависимостей без острой нужды: ценность проекта в том, что это один файл и статика.
